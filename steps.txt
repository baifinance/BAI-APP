ASANA WEBHOOK REGISTRATION / RE-REGISTRATION (no git push)

Each environment uses its own label: --hook linux / --hook windows / ...
The label is stored in the target URL as ?hook=<label>; secrets never collide.

Prereqs: ngrok -> http://localhost:8000 and Django runserver are running.
ASANA_WEBHOOK_ENABLED=True in backend/.env (already set).
Do NOT edit .env for the handshake flag; pass it inline (read_env does not
override OS env).

1. Apply pending migrations
   cd backend
   venv/bin/python manage.py migrate

2. List existing webhooks, then delete the stale/duplicate ones
   venv/bin/python manage.py register_asana_webhook --list
   venv/bin/python manage.py register_asana_webhook --delete <WEBHOOK_GID>

3. Clear only THIS environment's stale secret (skip if the label is new)
   venv/bin/python manage.py shell -c "from asana_integration.models import AsanaWebhookSecret as M; print(M.objects.filter(key='windows').delete())"

4. Restart runserver with the handshake gate open
   ASANA_WEBHOOK_HANDSHAKE_ENABLED=True venv/bin/python manage.py runserver

5. Register this environment (command appends ?hook=<label>)
   ASANA_WEBHOOK_HANDSHAKE_ENABLED=True venv/bin/python manage.py register_asana_webhook \
     --hook windows \
     --target https://<id>.ngrok-free.dev/api/asana/webhook

6. Verify
   venv/bin/python manage.py register_asana_webhook --list
   # expect: hook=windows, active=True, no last_failure_at
   venv/bin/python manage.py shell -c "from asana_integration.models import AsanaWebhookSecret as M; r=M.objects.filter(key='windows').first(); print(r.updated_at, len(r.secret) if r else None)"
   # expect: a timestamp and 32
   Move a task section in Asana and confirm an event is processed in the server log.

7. Re-close the gate
   Ctrl+C the server and restart WITHOUT ASANA_WEBHOOK_HANDSHAKE_ENABLED.

Notes
- Rotation is per label: registering 'windows' works while 'asana'/'linux'
  already has a secret. Replacing an existing label still needs
  ASANA_WEBHOOK_ALLOW_ROTATION=True.
- A target with no ?hook uses the legacy 'asana' label (old deployments keep
  working unchanged).
- Deleting a secret row is preferred over enabling ALLOW_ROTATION, which would
  let any unauthenticated caller overwrite the signing secret during the window.
- Never reuse the same label for two environments; one DB holds one secret
  per label.
- No code changes, commits, or pushes are required for registration.
